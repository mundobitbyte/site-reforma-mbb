9 — Backlog e MVP

A primeira entrega precisa atravessar um fluxo útil inteiro.

Organize trabalho e valor

Épico: atender pedidos. Funcionalidade: registrar uma venda. História: “Como atendente, quero registrar um pedido válido para preparar o que foi vendido sem perder o saldo”. Tarefa: agrupar quantidades no serviço. A tarefa técnica não substitui a necessidade da pessoa.

Os 3 Cs ajudam a anotar, conversar e confirmar: cartão registra a intenção, conversa esclarece regras, confirmação define os critérios. INVEST é apoio para revisar histórias pequenas e testáveis, não obrigação de decorar letras.

Backlog é uma lista ordenada de trabalho. Primeiro: produto → pedido/itens/estoque → consulta. Depois: cupom e estados. Segurança e integridade aplicáveis a cada fatia entram desde o começo.

MVP, Ready e Done

MVP é a menor versão coerente que entrega valor e permite aprender. O núcleo local executável é um piloto; ainda não foi validado como produto para uso real. Mais funções não substituem essa validação.

Story Map organiza pela jornada: escolher → conferir → registrar → acompanhar → entregar. Uma fatia atravessa a jornada em profundidade suficiente; não construa só um cadastro enorme.

Ready: regra, fonte, dados e critério estão claros para começar. Done: implementação e verificações aplicáveis passaram, limites estão registrados. Os 63 casos de servidor não fecham a interface a 360 px. A pendência não desaparece por reclassificá-la como concluída.

Faça agora

  • Organize uma fatia pela jornada.
  • Separe história de tarefa técnica.
  • Escreva uma condição de Done que ainda não foi comprovada.
