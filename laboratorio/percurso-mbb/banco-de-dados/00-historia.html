0 — História e necessidade dos dados

Guardar o pedido é só o começo: precisamos encontrá-lo e confiar nas relações.

O problema aparece antes da ferramenta

Imagine a Cantina usando uma anotação para o pedido, outra para o saldo e outra para a preparação. A informação pode divergir ou desaparecer. Colocar cada anotação em um arquivo digital não resolve sozinho a falta de ligação.

Banco de dados é o conjunto organizado de dados; SGBD é o software que os gerencia; SQL é uma linguagem para definir e consultar dados em ambientes relacionais. Eles não são três nomes para a mesma coisa.

O que mudou com o modelo relacional?

Em vez de misturar tudo numa linha longa, separamos Produto, Pedido e Item do Pedido, ligados por chaves. Assim consultamos a venda sem reescrever o cadastro a cada pedido. O modelo de Análise já explica por que essas relações existem.

A história também apresenta modelos hierárquicos, em rede, relacionais e famílias NoSQL. Eles respondem a problemas diferentes. Aqui a necessidade de relacionar itens, saldo e venda justifica o relacional; não migramos de tecnologia só porque apareceu uma opção mais recente.
