1 — Fundamentos

Uma tabela, uma linha e uma chave precisam representar coisas diferentes.

Dado, informação e estrutura

600 é um dado. “O suco custa 600 centavos e cinco unidades somam 3000” é informação contextualizada. Uma linha de produto representa uma ocorrência; suas colunas representam atributos como nome, preço e estoque. Domínio restringe valores possíveis.

PK identifica uma linha; FK relaciona uma linha a outra. Nome pode mudar e não precisa ser único: por isso o item aponta para o id do produto. NULL significa ausência de valor; cupom_codigo nulo é diferente de desconto igual a zero.

SQLite e MySQL não tratam tipos de forma idêntica. A evolução usa INTEGER e CHECK sobre o valor armazenado; a API usa tipos estritos para recusar entrada indevida. Afinidade de coluna pode converter um texto numérico antes do CHECK: não prometa que o schema sozinho conserva o tipo original recebido.

Dinheiro neste piloto é centavo inteiro: R$ 3,00 = 300. Datas do histórico são texto gerado em UTC; isso não torna qualquer texto uma data válida. Consulte tipos e afinidades no SQLite quando comparar ambientes.
