4 — SQL: MySQL e SQLite

O mesmo conceito precisa de comandos compatíveis com o ambiente escolhido.

Da pasta ao primeiro comando

Terminal é a janela em que você executa comandos. Para esta prática, use a cópia local do repositório experimental, não a pasta do site oficial. O site publicado mostra o material, mas não executa Python/SQLite no seu aparelho.

  1. Se já tem a pasta e o ambiente da Cantina, reutilize-os e vá à conferência dos arquivos. Caso contrário, no GitHub experimental selecione a branch publicacao/cantina-estatica, use Code → Download ZIP e extraia o ZIP. Entre em laboratorio/cantina-evolutiva dentro da pasta extraída.
  2. No Windows, nessa pasta pelo Explorador, digite cmd na barra de endereço e Enter: abre o Prompt na pasta certa. Os comandos Windows abaixo são para CMD, não PowerShell. Linux/macOS: abra o terminal nessa pasta.
  3. Confira laboratorio_bd.py, servico.py e schema-inicial.sql. “Arquivo não encontrado” indica pasta errada; ajuste a pasta, não recrie arquivos.
  4. Use Python 3.10 ou posterior. Se não estiver instalado, obtenha o instalador oficial em python.org e confirme a versão antes de continuar. SQLite já vem no módulo sqlite3 do Python; não precisa instalar MySQL para estas práticas.
Preparação Windows no CMD
py --version
dir laboratorio_bd.py

Se já existe .venv, ative-a; não precisa criá-la novamente. Se não existe:

py -m venv .venv
.venv\Scripts\activate.bat
Preparação Linux/macOS
python3 --version
ls laboratorio_bd.py

Se já existe .venv, ative-a. Se não existe:

python3 -m venv .venv
source .venv/bin/activate

Com o ambiente ativado, instale a base de fusos usada pelo cupom. Para BD, os demais pacotes da API não são necessários:

python -m pip install tzdata
python -c "import sys, sqlite3; print(sys.version); print(sqlite3.sqlite_version)"

A versão SQLite exibida deve ser 3.33 ou posterior para este roteiro. Se for anterior, atualize o Python/SQLite antes de usar sqlite_schema e as consultas de janela. Se o comando de instalação falhar, pare e registre a mensagem. Os laboratórios locais executáveis exigem computador; pelo celular você pode ler, desenhar e planejar, mas não declare execução SQL. Depois da confirmação, use python laboratorio_bd.py preparar abaixo. Não inicie o servidor da API para consultar o banco didático.

Referências oficiais: ativação de venv por sistema e SQLite 3.33.

Prepare a experiência sem alterar outro banco

Com a pasta e o ambiente conferidos acima, execute no terminal:

python laboratorio_bd.py preparar

O comando usa o mesmo schema, migrações e serviço; cria apenas dados/bd-didatico/cantina.sqlite3. O banco da aplicação e o da v1 não são usados. Se o arquivo já existe, a preparação recusa sem apagar ou reiniciar.

Dados iniciais: cinco produtos; pedido 1 com duas águas, total 600; pedido 2 com cinco sucos e MBB10, total 2700; dois eventos no pedido 1. Esses valores valem logo após preparar. Os experimentos de escrita dos capítulos seguintes mudam essa cópia.

Consulte antes de alterar

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 01-cardapio
SELECT id, nome, preco_centavos, estoque
FROM produto
ORDER BY id;

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 02-saldo-baixo
SELECT id, nome, estoque
FROM produto
WHERE estoque < 11
ORDER BY estoque, id;

SELECT escolhe colunas; FROM indica a origem; WHERE filtra linhas; ORDER BY explicita a ordem. Sem ORDER BY, não conte com a ordem da saída. DISTINCT elimina repetições do resultado; LIMIT restringe quantas linhas retorna. LIKE expressa padrões; comparações e funções podem variar conforme collation/ambiente.

Confira a estrutura criada pelo serviço

CREATE TABLE define a tabela; INSERT insere linhas; VIEW nomeia uma consulta; INDEX auxilia acesso. A preparação já executou o schema e as migrações próprios, sem simplificá-los. Leia a estrutura real, sem reexecutar criação no mesmo banco:

python laboratorio_bd.py consultar 16-estrutura
SELECT type, name, sql
FROM sqlite_schema
WHERE type IN ('table', 'view', 'index')
  AND name NOT LIKE 'sqlite_%'
ORDER BY type, name;

Arquivo da inspeção. São cinco tabelas, a visão resumo_pedido e índices; o índice automático de chave pode não aparecer neste filtro. PRAGMA é uma instrução SQLite para configuração/inspeção; a rotina verificar usa integridade, FKs e versão.

A ponte sem tradução automática

NecessidadeMySQL do acervoSQLite desta evolução
Selecionar baseCREATE DATABASE / USEArquivo aberto pela conexão
IdentificadorAUTO_INCREMENT nos exemplosINTEGER PRIMARY KEY no schema
Inspecionar estruturaDESCRIBE / SHOW CREATE TABLESchema versionado e sqlite_schema/PRAGMA
Alterar estruturaALTER TABLE tem regras do servidorMigrações próprias, uma vez, pelo serviço
Dados novosINSERT na base própria de exercíciosPreparação pelo serviço e transação didática
Alterar/excluirUPDATE / DELETE com alvo e contextoExperimento controlado; nenhuma exclusão de venda no produto
TiposTipos do servidor, como DECIMALAfinidade e CHECK; centavos inteiros neste caso

Não copie CREATE DATABASE, USE, AUTO_INCREMENT, SHOW ou mysqldump para a conexão SQLite. Os scripts completos de comercio e loja_integrador continuam no acervo. Para estrutura da Cantina, use o schema e suas migrações, não os execute de novo num banco já criado.

Prepare e interprete a primeira execução

Precisamos de um arquivo próprio para fazer perguntas com SQL. Use a preparação guiada abaixo antes do primeiro comando; SQL aparece nos blocos para leitura/cópia, mas os comandos começados com python são os que você executa no terminal. O programa abre o SQLite e executa o arquivo SQL indicado.

Ver exemplo didático — não é evidência do aluno

Logo após preparar: cinco produtos; estoques Água 18, Suco 10, Salgado 10, Sanduíche 8, Chocolate 12. Foram inseridos dois pedidos, por isso Água e Suco já tiveram baixa.
