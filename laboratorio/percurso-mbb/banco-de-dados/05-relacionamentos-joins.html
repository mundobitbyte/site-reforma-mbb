5 — Relacionamentos e JOIN

A consulta recompõe o que o modelo separou conscientemente.

Relacionamento não é consulta

FK faz parte da estrutura e restringe vínculos. JOIN compõe um resultado usando uma condição; não funde fisicamente as tabelas. O pedido completo precisa de Pedido, Item e Produto: junte pelos identificadores correspondentes, não por nomes parecidos.

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 03-pedido-completo
SELECT p.id AS pedido_id, p.status, pr.nome,
       i.quantidade, i.preco_unitario_centavos,
       i.quantidade * i.preco_unitario_centavos AS valor_item_centavos
FROM pedido AS p
JOIN item_pedido AS i ON i.pedido_id = p.id
JOIN produto AS pr ON pr.id = i.produto_id
WHERE p.id = 1
ORDER BY i.produto_id;

Aliases tornam a leitura curta; primeiro explique p, i e pr. O valor do item usa o preço histórico. Trocar pelo preço atual do produto reescreveria a informação da venda.

Quem ficou sem correspondência?

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 05-nunca-vendidos
SELECT p.id, p.nome
FROM produto AS p
LEFT JOIN item_pedido AS i ON i.produto_id = p.id
WHERE i.pedido_id IS NULL
ORDER BY p.id;

LEFT JOIN mantém os produtos à esquerda, incluindo os que não aparecem em item. O filtro IS NULL responde quem nunca vendeu. INNER JOIN os omitiria. RIGHT JOIN preserva o outro lado quando suportado pelo ambiente; neste roteiro basta inverter a ordem e raciocinar com LEFT JOIN.

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 06-vendas-por-produto
SELECT p.id, p.nome, COUNT(i.pedido_id) AS pedidos_com_produto,
       COALESCE(SUM(i.quantidade), 0) AS unidades_vendidas,
       COALESCE(SUM(i.quantidade * i.preco_unitario_centavos), 0) AS subtotal_vendido_centavos
FROM produto AS p
LEFT JOIN item_pedido AS i ON i.produto_id = p.id
GROUP BY p.id, p.nome
ORDER BY p.id;

COUNT(i.pedido_id) conta correspondências reais; COUNT(*) também contaria a linha preservada sem venda. COALESCE transforma a soma ausente em zero. No estado inicial, esse relatório soma 3600 centavos antes do desconto; os pedidos somam 3300 após o cupom. Não distribuímos o desconto por produto. WHERE filtra linhas; HAVING filtra grupos; um filtro da tabela direita no WHERE pode eliminar os casos que o LEFT JOIN queria manter.

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 07-historico
SELECT p.id AS pedido_id, p.status,
       h.estado_anterior, h.estado_novo, h.alterado_em
FROM pedido AS p
LEFT JOIN historico_status AS h ON h.pedido_id = p.id
ORDER BY p.id, h.id;

Pedido 2 permanece na consulta mesmo sem evento. Produto cartesiano pode multiplicar linhas quando falta a condição de associação; antes de somar, confira as cardinalidades da consulta.
