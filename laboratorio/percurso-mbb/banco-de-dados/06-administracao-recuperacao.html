6 — Administração e recuperação

Uma cópia só sustenta recuperação quando conseguimos usá-la de novo.

SGBDs e ambientes diferentes

No MySQL, servidor, cliente, conta/origem e permissões são conceitos distintos; Workbench é uma interface, não o banco. No SQLite do piloto, a aplicação usa uma biblioteca e um arquivo. Não existe uma transposição automática de GRANT ou usuário root para esse arquivo.

A rotina de consulta abre o banco didático em modo somente leitura. Permissões do arquivo e do computador continuam relevantes; isso não cria autenticação por aluno. O laboratório não solicita mudança de contas, porta 3306, Firebase ou produção.

No acervo MySQL, preserve o ambiente indicado para comandos de shell e de SQL, as contas de privilégio mínimo, SHOW GRANTS/REVOKE e os laboratórios de dump/restauração. O serviço da Cantina não substitui essas capacidades de administração do servidor.

Backup binário e restauração em outro arquivo

python laboratorio_bd.py verificar
python laboratorio_bd.py backup
python laboratorio_bd.py restaurar

Backup usa a API de cópia do SQLite, gerando backup.sqlite3. Restaurar cria restaurado.sqlite3; não volta por cima da origem. A rotina verifica integridade, vínculos e contagens. Destino existente é recusado.

Primeira rodada: faça backup e restaure, comparando a cópia com a base. Depois de estudar COMMIT no capítulo 7, volte: crie a cópia antes de uma nova venda, confirme a venda na origem e compare com a restauração anterior. A origem deve manter a venda posterior. Reabrir um banco não é o mesmo teste que recuperar uma cópia. Documentação oficial da API de backup.

SQL com tabelas e registros

python laboratorio_bd.py exportar
python laboratorio_bd.py restaurar-sql

A exportação gera cantina.sql a partir do banco: estrutura, registros, visão e índice; acrescenta a versão de migração. A restauração cria restaurado-sql.sqlite3. Assim não mantemos um segundo script de dados iniciais manualmente divergente.

O dump próprio pode inserir filhos antes de pais. A rotina carrega em arquivo novo, habilita FK depois e verifica violações ao final. Habilitar FK vale para aquela conexão; as próximas escritas continuam exigindo sua própria ativação, como faz o serviço. Essa operação se destina à exportação criada pelo próprio roteiro. A exportação SQL não inclui contas MySQL, arquivos do projeto nem toda a máquina.

Disponibilidade, retenção, cópia fora da máquina e recuperação de desastre são outras decisões. A prática comprova esta cópia local; não afirma que uma política real de backup esteja concluída.

Faça agora

  • Diferencie banco, cliente e servidor nos dois ambientes.
  • Prove que a origem não foi substituída ao restaurar.
  • Compare backup de arquivo e dump SQL; anote o que cada um não inclui.
