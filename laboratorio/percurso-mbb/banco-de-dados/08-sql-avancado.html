8 — SQL Avançado

Use outra forma de consulta quando ela esclarecer uma pergunta concreta.

Subconsulta e CTE

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 09-sem-venda-exists
SELECT p.id, p.nome
FROM produto AS p
WHERE NOT EXISTS (
    SELECT 1 FROM item_pedido AS i WHERE i.produto_id = p.id
)
ORDER BY p.id;

NOT EXISTS pergunta se não há item associado. Compare o resultado com LEFT JOIN + IS NULL: duas representações da mesma pergunta, sem afirmar que uma será sempre mais rápida.

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 10-cte
WITH totais AS (
    SELECT id, subtotal_centavos - desconto_centavos AS total_centavos
    FROM resumo_pedido
)
SELECT id, total_centavos
FROM totais
WHERE total_centavos >= 1000
ORDER BY id;

WITH dá nome a uma etapa. O total por pedido continua derivado de preço histórico menos desconto. IN/EXISTS/subconsulta escalar resolvem perguntas diferentes. UNION empilha resultados, não associa colunas como JOIN; UNION ALL conserva repetições.

Janela sem desaparecer com as linhas

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 11-acumulado
SELECT id, subtotal_centavos - desconto_centavos AS total_centavos,
       SUM(subtotal_centavos - desconto_centavos)
           OVER (ORDER BY id ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS acumulado_centavos
FROM resumo_pedido
ORDER BY id;

GROUP BY produz grupos; a janela acrescenta um cálculo mantendo as linhas de pedido. Aqui a ordem id e a moldura ROWS definem o acumulado, não a ordem implícita do banco.

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 12-ranking
WITH vendas AS (
    SELECT p.id, p.nome, COALESCE(SUM(i.quantidade), 0) AS unidades
    FROM produto AS p
    LEFT JOIN item_pedido AS i ON i.produto_id = p.id
    GROUP BY p.id, p.nome
)
SELECT id, nome, unidades, RANK() OVER (ORDER BY unidades DESC) AS posicao
FROM vendas
ORDER BY posicao, id;

RANK conserva empate de posição. Os produtos sem venda entram com zero; não esconda esses casos. ROW_NUMBER numera linhas, mesmo se houver empate; escolha a função pela pergunta.

Visão, índice e comportamento automático

Arquivo SQL desta consulta. Execute no terminal, na pasta laboratorio/cantina-evolutiva, com o ambiente ativado:

python laboratorio_bd.py consultar 13-plano-historico
EXPLAIN QUERY PLAN
SELECT estado_anterior, estado_novo, alterado_em
FROM historico_status
WHERE pedido_id = 1
ORDER BY id;

resumo_pedido é uma VIEW: consulta nomeada, não cópia automática de dados. O índice de histórico ajuda a localizar eventos de um pedido; o plano desta base mostrou seu uso, não uma melhoria de tempo comprovada. Índice também tem custo de manutenção.

No acervo, EXPLAIN/EXPLAIN ANALYZE, trigger, procedure e function têm papéis distintos. Não copiamos rotinas CALL para SQLite. A regra de venda permanece visível no serviço; as triggers de falha dos testes são instrumentos de teste, não funcionalidade prometida ao usuário.
