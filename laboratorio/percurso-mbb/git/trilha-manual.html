Git — trilha manual isolada

Esta trilha é manual, com dados fictícios e repositórios locais isolados. Faça em ordem, uma etapa por vez. Os arquivos são criados/editados no editor, os comandos no terminal. Não cole todos os blocos de uma vez: há edições entre eles. Instalar Git. O executor de 62 comandos permanece como verificação independente; executá-lo não significa que você fez a trilha manual.

GIT00 — Preparar uma pasta isolada

Crie no Explorador uma pasta nova e vazia chamada cantina-git-aula, fora de qualquer repositório existente. Se já existir, escolha outro nome e adapte os caminhos seguintes. Abra cmd pela barra de endereço. Instale Git pelo site oficial se necessário. No Linux/macOS use pwd para conferir a pasta; no Windows, cd sem argumento.

git --version
git init -b aula
git config user.name "Aluno Cantina"
git config user.email "aluno@example.invalid"
git config commit.gpgsign false
git status

Conferir: Git 2.28 ou superior; branch aula, sem commits. As configurações são somente deste repositório. Não inicialize sobre o site ou outra pasta de trabalho.

Registre sua observação em GIT00. ← Voltar à etapa

GIT01 — Registrar uma regra

Na pasta cantina-git-aula, crie requisitos.md em editor de texto UTF-8, contendo uma linha: RF-03: quantidade inteira de 1 a 10. Salve antes de executar.

git status
git diff
git add requisitos.md
git diff --cached
git commit -m "Registra RF-03"
git status

Conferir: Antes do add, o arquivo é untracked e não aparece no diff comum. Após add, diff --cached mostra a proposta do commit. Ao concluir, working tree clean.

Registre sua observação em GIT01. ← Voltar à etapa

GIT02 — Investigar uma alteração

Ainda na mesma pasta, altere a linha para RF-03: quantidade inteira de 1 a 11. Esta mudança errada é fictícia e será revertida na próxima etapa.

git diff
git add requisitos.md
git commit -m "Experimento com limite 11"
git log --oneline
git show HEAD
git show HEAD~1:requisitos.md

Conferir: Dois commits; show HEAD mostra a troca 10→11. HEAD~1:requisitos.md mostra o conteúdo do primeiro commit, sem mudar o arquivo atual. Anote o hash do primeiro commit para GIT06.

Registre sua observação em GIT02. ← Voltar à etapa

GIT03 — Desfazer com intenção

Na mesma pasta, reverta o último commit. Depois acrescente a linha Rascunho de aula. ao arquivo e salve; execute apenas o segundo bloco após essa edição.

git revert --no-edit HEAD
git log --oneline -3
git status

Conferir: Revert cria um terceiro commit que devolve 10, preservando o histórico. Depois use o bloco abaixo: restore --staged retira a proposta do índice, preservando sua edição; restore requisitos.md descarta a edição local. Só descarte o rascunho fictício desta pasta, após conferir o diff.

Após acrescentar o rascunho fictício

git add requisitos.md
git diff --cached
git restore --staged requisitos.md
git diff --cached
git diff
git restore requisitos.md
git status

Registre sua observação em GIT03. ← Voltar à etapa

GIT04 — Experimentar em branch

Na mesma pasta, execute switch -c. Nessa branch, crie justificativa.md com a linha Limite aprovado: 10 por produto. Salve, então execute os demais comandos.

git switch -c experimento/justificativa

Agora crie justificativa.md no editor, salve e execute:

git add justificativa.md
git commit -m "Explica limite"
git switch aula
git status
git merge --ff-only experimento/justificativa

Conferir: Antes do merge, justificativa.md não aparece em aula; depois aparece. A branch temporária não é a branch de publicação do laboratório.

Registre sua observação em GIT04. ← Voltar à etapa

GIT05 — Resolver um conflito real

Crie a branch abaixo e troque a primeira linha de requisitos.md para RF-03: quantidade inteira de 1 a 12. Salve e registre. Volte a aula, troque a mesma linha para RF-03: quantidade inteira de 1 a 10 por produto consolidado. Salve e registre. Execute cada bloco no momento indicado.

git switch -c experimento/limite12

Agora edite requisitos.md para o limite fictício 12, salve e execute:

git add requisitos.md
git commit -m "Experimenta limite 12"
git switch aula

Conferir: Depois do segundo bloco, merge retorna CONFLICT e código de saída não zero: é o conflito esperado. Abra requisitos.md, remova todos os marcadores <<<<<<<, =======, >>>>>>> e mantenha a regra aprovada de 1 a 10 por produto consolidado. Salve, add e commit conforme o terceiro bloco. Conferir ausência de arquivos não resolvidos não prova por si só que a regra escolhida é correta; leia a linha.

Em aula, depois de salvar a regra consolidada

git add requisitos.md
git commit -m "Consolida regra aprovada"
git merge experimento/limite12
git status
git diff --name-only --diff-filter=U

Depois de resolver o arquivo no editor

git add requisitos.md
git commit -m "Resolve conflito conforme RF-03"
git diff --name-only --diff-filter=U
git status

Registre sua observação em GIT05. ← Voltar à etapa

GIT06 — Consultar uma versão

Na mesma pasta, substitua HASH pelo hash do primeiro commit anotado em GIT02, sem digitar a palavra HASH.

git log --oneline
git show HASH:requisitos.md
git status

Conferir: A consulta mostra a regra original, sem trocar a branch, restaurar arquivos ou descartar mudanças. O arquivo atual continua com a regra consolidada. Consultar não é voltar a operar naquela versão.

Registre sua observação em GIT06. ← Voltar à etapa

GIT07 — Sincronizar sem GitHub

De cantina-git-aula, crie um remoto bare local na pasta pai. Não entre para editar seus arquivos internos. Todos os caminhos abaixo são locais; nenhum comando usa rede, autenticação ou repositório oficial. Use nomes novos se as pastas já existirem.

cd ..
git init --bare -b aula remoto-cantina.git
cd cantina-git-aula
git remote add origin ../remoto-cantina.git
git remote -v
git push -u origin aula
cd ..
git clone remoto-cantina.git cantina-colega
cd cantina-git-aula

Conferir: Agora há uma cópia cantina-colega. Na pasta cantina-git-aula, crie parecer.md com Uso didatico; nao e liberacao comercial. Salve e execute o segundo bloco. Fetch atualiza origin/aula na cópia colega, mas não altera o arquivo atual; pull --ff-only integra sem inventar merge; push envia os commits para o remoto bare local.

Na pasta cantina-git-aula, depois de salvar parecer.md

git add parecer.md
git commit -m "Registra parecer didatico"
git push
cd ../cantina-colega
git log --oneline -1
git fetch origin
git log --oneline -1
git log --oneline origin/aula -1
git diff HEAD..origin/aula
git pull --ff-only origin aula
git log --oneline -1
cd ../cantina-git-aula

Registre sua observação em GIT07. ← Voltar à etapa

GIT08 — Ignorar e revisar

Volte à pasta cantina-git-aula. Crie .gitignore com duas linhas: *.sqlite3 e .venv/. Crie ensaio.sqlite3 como arquivo de texto fictício vazio; não copie nem abra um banco verdadeiro.

git check-ignore ensaio.sqlite3
git ls-files ensaio.sqlite3
git status
git add .gitignore
git diff --cached
git diff --check
git commit -m "Ignora dados locais"
git status

Conferir: check-ignore aponta o arquivo; ls-files não o lista; o commit inclui apenas .gitignore. Ignorar não remove arquivos já rastreados e não protege segredo já publicado. Revise arquivos, regra, diff e resultado antes de aprovar.

Registre sua observação em GIT08. ← Voltar à etapa

GIT09 — Marcar uma entrega didática

Na mesma pasta, depois de revisar a regra e os resultados, crie uma tag local.

git tag -a cantina-didatica-v1 -m "Entrega didatica revisada"
git show --no-patch cantina-didatica-v1
git log --oneline --decorate -5
git status

Conferir: A tag aponta a versão revisada; a árvore está limpa. Não há obrigação de publicar a tag ou criar remoto GitHub. Registre o commit, a tag, os testes reais e seus limites; esta entrega não libera operação comercial.

Registre sua observação em GIT09. ← Voltar à etapa
