12 — O terminal usa o mesmo serviço e banco

A simulação precisa chegar a uma venda fictícia persistente sem copiar todas as regras para o terminal.

Antes de programar

A simulação precisa chegar a uma venda fictícia persistente sem copiar todas as regras para o terminal.

Pré-requisitos: Etapas 0–11; BD03/BD04/BD07.

Conceitos que resolvem esta necessidade

contrato do serviço, parâmetro SQL, transação, adaptador de terminal, argparse.

Agora use terminal.py, no mesmo projeto do serviço. Essa interface converte argumentos e apresenta resultados; Cantina mantém validação, consolidação, preço histórico, cupom, estoque e transação.

argparse, da biblioteca padrão, lê comandos e opções. --item 1:2 significa produto 1, quantidade 2; repetir a opção envia outra linha. A conversão é do terminal; faixa, produto e saldo são conferidos pelo serviço. Valores SQL são ligados aos placeholders ?, separados do texto do comando.

O banco desta prática fica em laboratorio/cantina-evolutiva/dados/programacao/cantina.sqlite3. Ele usa o mesmo schema e migrações, com dados fictícios; preserva o banco da interface Web e a prática de BD. Preparar é feito uma vez e recusa recomeçar um banco existente. Não passe caminho externo ao CLI.

  1. Volte à raiz da cópia experimental e siga o ambiente virtual já documentado.
  2. Na pasta laboratorio/cantina-evolutiva, com o ambiente ativado, execute os comandos abaixo um por vez.
  3. Anote o ID retornado pelo registro. A consulta 1 abaixo só corresponde à primeira venda em um banco novo.
  4. Feche e reabra o terminal, reative o ambiente e consulte esse mesmo ID. Não repita registrar só para conferir: cada sucesso cria outra venda.

BEGIN IMMEDIATE inicia a escrita antes de ler o saldo usado na venda. Gravação de pedido, item, estoque e eventual cupom é confirmada ou revertida em conjunto. Retome a evidência BD07. Contar linhas não prova a interface Web ou o comportamento de várias pessoas.

Prática com código completo

Criar uma vez

python terminal.py preparar

Consultar cadastro

python terminal.py produtos

Registrar primeira venda fictícia

python terminal.py registrar --item 1:2

Consultar ID retornado

python terminal.py consultar 1

Avançar com estado conferido

python terminal.py avancar 1 --estado-esperado Novo

Preveja, execute e compare

Banco novo: Água 300/saldo 20; primeira venda 2 Águas, subtotal/total 600, saldo 18. Estado vai de Novo para Confirmado com um evento.

Consulte a venda salva e tente usar outra vez estado-esperado Novo: deve recusar.

Evidência desta etapa

PG12: comando, retorno salvo, reabertura e transição; reusa BD07/BD09/RF-01 a RF-09.

Registre previsão, execução, diferença, limite e reteste no caderno.
