4 — O evento transforma entrada em previsão

Ao confirmar o formulário, a tela deve calcular uma simulação sem recarregar ou anunciar venda inexistente.

Antes de construir

Ao confirmar o formulário, a tela deve calcular uma simulação sem recarregar ou anunciar venda inexistente.

Pré-requisitos: WEB00–WEB03; PG03/PG07/PG08.

Conceitos por necessidade

const, function, DOM, querySelector, evento submit, preventDefault, Number, textContent, defer, Number.isInteger, !, ||, return, template literal, modo estrito.

JavaScript usa const para uma associação que não será reatribuída. function define a operação; um parâmetro recebe o evento. querySelector encontra um elemento no DOM, a representação do documento. addEventListener registra o que fazer quando ocorrer submit.

preventDefault evita a ação padrão desse envio; Number converte o texto do campo. Number.isInteger e as comparações conferem a faixa. textContent apresenta texto sem interpretá-lo como HTML. defer faz o script esperar a análise do documento.

Leia a condição com o que já aprendeu em Python: ! nega o resultado, e || reúne alternativas, como or nas decisões de PG03. return; encerra a função após a recusa; o subtotal só é calculado no caminho válido.

O texto final usa um template literal: as crases delimitam a string e ${subtotal_centavos} insere o valor, como as expressões entre chaves da f-string de PG02. A linha "use strict"; ativa o modo estrito de JavaScript, que torna certos usos incorretos da linguagem erros explícitos.

A função calcula quantidade × 300 como PG01; nada é gravado. Essa previsão não verifica estoque real nem cupom. Para um teste de recusa em navegador, a validação nativa pode impedir o submit antes do handler: registre qual camada recusou, sem confundi-las.

04-simulacao/app.js

"use strict";
const formulario = document.querySelector("#simulacao");
const campo = document.querySelector("#quantidade");
const resultado = document.querySelector("#resultado");

function simular(evento) {
  evento.preventDefault();
  const quantidade = Number(campo.value);
  if (!Number.isInteger(quantidade) || quantidade < 1 || quantidade > 10) {
    resultado.textContent = "Use uma quantidade inteira de 1 a 10.";
    return;
  }
  const subtotal_centavos = quantidade * 300;
  resultado.textContent = `Simulação: ${subtotal_centavos} centavos. Nenhuma venda registrada.`;
}

formulario.addEventListener("submit", simular);

Como executar e conferir

Na cópia extraída, abra laboratorio/percurso-mbb/web-api/exemplos/04-simulacao. Arquivos dessa atividade: index.html, styles.css, app.js. Preserve os nomes e mantenha os arquivos juntos. Antes de alterar, faça uma cópia dessa pasta para seu exercício.

Abra os arquivos num editor de texto. Para criar um arquivo, cole o código completo, salve em UTF-8 com o nome indicado e escolha “Todos os arquivos” se o editor oferecer essa opção; confira que não virou .html.txt. Salve com Ctrl+S. Abra index.html no navegador e recarregue após editar.

Estas páginas estáticas podem abrir diretamente como arquivo local. Não registram vendas nem consultam a API. A atividade de API a partir de WEB06 exige servidor HTTP. Aqui a evidência é o que aparece e funciona na página; não invente um código HTTP.

Quantidade 2 → evento de envio → validar inteiro de 1 a 10 → subtotal previsto 600 centavos. Primeiro o navegador verifica as restrições HTML; se barrar 0, o evento pode nem chegar ao JavaScript. Depois o código confere a entrada. Previsão não é venda gravada.

Preveja, experimente e compare

Preveja 2 → 600; identifique o texto que deixa clara a simulação e o caminho da recusa.

Registre o que espera antes de executar. Acrescente resultado real, diferença e limite depois; as verificações de código desta adaptação não são teste visual ou sessão com aluno.
