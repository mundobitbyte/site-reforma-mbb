9 — Consultar antes de avançar

A preparação precisa continuar a partir do estado salvo, sem pular ou avançar uma consulta antiga.

Antes de construir

A preparação precisa continuar a partir do estado salvo, sem pular ou avançar uma consulta antiga.

Pré-requisitos: WEB00–WEB08; PG12.

Conceitos por necessidade

ID retornado, proximo_status, estado_esperado, 409, controle de resposta antiga.

A consulta devolve o estado salvo, próximo passo e histórico. O avanço envia o próximo e o estado exibido. O servidor compara a consulta com o estado atual e recusa conflito com 409. Novo → Confirmado → Em preparação → Pronto → Entregue é a sequência aprovada.

O módulo abaixo monta a mesma intenção; se não há próximo passo, não envia. O servidor continua conferindo a transição e gravando estado/evento juntos. Avançar não recalcula o preço nem baixa estoque novamente.

Na interface existente, um contador de versão identifica a consulta. Uma resposta só substitui o pedido mostrado quando pertence à versão atual. Isso evita que uma consulta atrasada sobrescreva outra tarefa já iniciada. O guardião no cliente organiza a tela; o estado esperado no servidor protege a mudança.

Depois de uma recusa, consulte novamente. Não tente adivinhar um estado para forçar sucesso. Entregue encerra a sequência; não existe cancelamento ou exclusão de venda no núcleo atual.

Prática com arquivos completos

09-estados.mjs

import { solicitar } from './api.mjs';

export async function avancarPedido(base, pedidoConsultado) {
  if (!pedidoConsultado.proximo_status) {
    throw new Error('O pedido consultado não tem uma próxima etapa disponível.');
  }
  return solicitar(base, `pedidos/${pedidoConsultado.id}/status`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      status: pedidoConsultado.proximo_status,
      estado_esperado: pedidoConsultado.status,
    }),
  });
}
