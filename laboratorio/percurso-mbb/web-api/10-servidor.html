10 — Validar na fronteira e operar no serviço

O navegador pode enviar texto, booleano, preço alterado ou uma intenção que perdeu validade.

Antes de construir

O navegador pode enviar texto, booleano, preço alterado ou uma intenção que perdeu validade.

Pré-requisitos: WEB00–WEB09; BD07/PG11/PG12.

Conceitos por necessidade

modelo de entrada, Pydantic estrito, campos extras, FastAPI, serviço, transação, mesma origem.

Na API existente, ItemEntrada exige inteiro estrito positivo para produto_id e inteiro 1–10 para quantidade; PedidoEntrada exige lista não vazia e cupom texto/null. Campos extras são recusados. O modelo de status exige dois textos. Pydantic valida a estrutura; o serviço verifica produto, soma, saldo, cupom e sequência.

Leia app.py e servico.py: uma rota recebe a entrada e chama Cantina. O banco usa placeholders, preço histórico e transação. Não vamos reimplementar essas regras no JavaScript nem trocar sqlite3 por ORM só para acompanhar o acervo.

A aplicação serve interface e API na mesma origem (esquema/host/porta). Se forem separadas, analisar CORS conforme a origem necessária. CORS limita certas leituras de navegador; não autentica usuário nem protege sozinho o servidor contra outros clientes. Não usar no-cors como solução: ele não libera a leitura normal do JSON bloqueado.

O acervo aborda sessão, CSRF, autenticação, JWT e papéis. Esses conceitos continuam preservados como aprofundamento: a Cantina atual não tem identidades/autorizações e não recebe garantia de uso real por compartilhar tais referências.

Preveja, experimente e compare

Escolha um erro estrutural e um conflito de domínio e mostre quem os recusa.

Registre o que espera antes de executar. Acrescente resultado real, diferença e limite depois; as verificações de código desta adaptação não são teste visual ou sessão com aluno.
