Contrato HTTP da Cantina

O que o cliente pede e o que o servidor confirma.

Contrato observado no código existente

Base local de exemplo: http://127.0.0.1:8001. Inicie o servidor antes de usar. Os modelos de saída listados são campos relevantes; não representam resposta completa com datas e ID inventados.

Método e rotaSucessoEfeito
GET /api/produtos200Consultar cadastro; não registrar venda.
POST /api/pedidos201Uma nova venda fictícia aceita grava pedido/itens, baixa estoque e eventual cupom em uma transação.
GET /api/pedidos/{pedido_id}200Consultar ID devolvido; manter preço e desconto da venda.
POST /api/pedidos/{pedido_id}/status200Avançar só o próximo estado; mudança e evento juntos, sem nova baixa.

GET /api/produtos

Campos relevantes de resposta: id, nome, preco_centavos, estoque.

POST /api/pedidos

Campos relevantes de resposta: id, status, subtotal_centavos, desconto_centavos, total_centavos, itens, proximo_status, historico_status.

Corpo JSON de exemplo

{
  "itens": [
    {
      "produto_id": 1,
      "quantidade": 2
    }
  ],
  "cupom": null
}

GET /api/pedidos/{pedido_id}

Campos relevantes de resposta: id, status, subtotal_centavos, desconto_centavos, total_centavos, itens, proximo_status, historico_status.

POST /api/pedidos/{pedido_id}/status

Campos relevantes de resposta: id, status, proximo_status, historico_status.

Corpo JSON de exemplo

{
  "status": "Confirmado",
  "estado_esperado": "Novo"
}

Tipos, recusas e falta de resposta

  • produto_id: inteiro estrito positivo
  • quantidade: inteiro estrito de 1 a 10 em cada linha e após consolidar por produto
  • itens: lista não vazia
  • cupom: texto opcional ou null
  • campos_extras: recusados pelo servidor, inclusive preço/total/desconto enviados como autoridade
StatusSignificado neste contrato
400Regra de domínio recusada, por exemplo quantidade consolidada ou cupom abaixo do mínimo.
404Produto ou pedido não encontrado.
409Conflito: estoque insuficiente, cupom utilizado ou estado antigo/transição recusada.
422Estrutura, campo ou tipo de entrada inválido.
503Erro de banco tratado pelo servidor; esta tentativa de banco foi revertida.

Falha de comunicação pode ocorrer após a gravação. Não confirmar ausência de venda nem repetir POST automaticamente.

O ID de consulta é o retornado no registro. GET não registra nem baixa; POST de venda aceita cria uma nova venda; POST de status muda andamento sem nova baixa. Há outras respostas do framework, como rota ou método desconhecido: esta tabela descreve as operações e erros do núcleo.

Contrato em JSON · Código da API. CORS, botão desabilitado e campos HTML não são autenticação ou autorização.
